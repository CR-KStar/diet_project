로그인 유지와 프로필 저장 학습 노트

앱을 껐다 켜도 로그인과 온보딩이 유지되도록 고친 과정을 정리했어요. 2026-09-21 기준이고, 코드 위치는 문서를 만들 때 실제 파일에서 읽어 왔어요.

한 줄 요약. 로그인 상태 확인, 입력값 저장, 마지막 버튼의 저장 호출 — 이 세 고리가 모두 이어져야 "껐다 켜도 그대로"가 돼요. 하나가 빠져 있었어요.

1. 처음 문제

앱을 종료했다가 다시 켜면 로그인 화면부터 다시 나오고, 온보딩도 처음부터 해야 했어요. Firebase 콘솔에도 저장된 값이 하나도 없었어요.

2. 원인은 세 겹이었어요

#원인설명
①앱이 시작할 때 "이미 로그인했나?"를 확인하지 않았어요.Firebase는 로그인 상태를 기기에 기억해 두는데, 앱이 그걸 물어보지 않고 항상 로그인 화면부터 보여 줬어요.
②입력한 값이 메모리에만 있었어요.닉네임 · 키 · 몸무게 같은 값은 앱을 끄면 사라졌고, "온보딩을 끝냈다"는 표시도 어디에도 없었어요.
③마지막 "시작하기" 버튼이 저장 없이 이동만 했어요.저장 코드를 넣었는데 이 파일에서만 예전 코드로 돌아가 있었어요. 그래서 onboardingDone이 계속 false였어요.

5. 핵심 코드 읽기

아래 세 함수가 이번 작업의 뼈대예요. 위에서 아래로 읽어 보세요.

① 앱을 켤 때 — restoreSession app_state.dart:154

  Future<bool> restoreSession() async {
    final current = await _auth.restoreAccount();
    if (current == null) return false;
    if (!await _enter(current)) return false;
    goAfterLogin();
    return true;
  }

로그인된 계정이 있으면 프로필을 불러오고(_enter), 성공하면 알맞은 화면으로 보내요.

② 단계를 넘길 때 — goToStep app_state.dart:188

  Future<void> goToStep(int next) async {
    step = next;
    notifyListeners();
    if (!await _persist()) {
      _backgroundError = authError;
      authError = null;
      notifyListeners();
    }
  }

화면을 먼저 넘기고, 저장은 뒤에서 해요. 저장이 실패해도 화면은 막지 않고 안내만 남겨요.

③ 끝낼 때 — completeOnboarding app_state.dart:234

  Future<bool> completeOnboarding() async {
    final before = onboardingDone;
    onboardingDone = true;
    if (!await _persist()) {
      onboardingDone = before;
      notifyListeners();
      return false;
    }
    go('home');
    return true;
  }

저장이 성공했을 때만 홈으로 가요. 실패하면 완료 표시를 되돌리고 화면에 머물러요.

가장 결정적이었던 수정 — "시작하기" 버튼 onboarding_page.dart:637

예전 
onTap: () {
  s.go('home');
  toast(context, '환영해요! 오늘 첫 기록을 시작해볼까요?');
},
지금 
onTap: () async {
  final saved = await s.completeOnboarding();
  if (!context.mounted) return;
  toast(context, saved ? '환영해요! 오늘 첫 기록을 시작해볼까요?' : (s.authError ?? '저장하지 못했어요'));
},

s.go('home')은 화면만 바꿀 뿐 아무것도 저장하지 않아요. await s.completeOnboarding()은 저장을 기다렸다가 결과에 따라 움직여요. 이 한 줄의 차이가 onboardingDone이 false로 남은 이유였어요.

7. 이번에 배운 점

배운 점왜 그런가
저장했다고 생각한 코드가 실제로 실행되는지 직접 확인하세요.로그에 저장 실패가 하나도 없는데 값이 안 바뀐 게 단서였어요. "실패가 없다"는 건 "저장을 시도했다"가 아니라 "시도 자체가 없었다"일 수 있어요.
기능은 한 곳만 고쳐서는 끝나지 않아요.로그인 상태 확인 → 프로필 불러오기 → 화면 이동 → 저장까지 모두 이어져야 동작해요. 한 고리가 빠지면 겉보기엔 "안 되는" 것처럼 보여요.
테스트는 실제 화면의 버튼까지 눌러 봐야 이런 누락을 잡아요.함수 자체를 검사한 테스트는 통과했는데, 그 함수를 부르는 버튼이 빠진 건 못 잡았어요. 그래서 화면 테스트를 추가했어요.
환경이 결과를 바꿀 수 있어요.에뮬레이터는 앱을 새로 설치하면 로그인 정보가 사라져요. 옵션을 빼고 실행하면 가짜 로그인(Mock)으로 돌 수도 있었어요. 어떤 환경에서 실행했는지 로그로 남겨 두면 좋아요.
편집기가 예전 내용으로 파일을 덮어쓸 수 있어요."디스크에서 다시 불러오기"를 습관으로 만드세요. 같은 파일을 도구와 IDE가 함께 만질 때 특히 조심하세요.
