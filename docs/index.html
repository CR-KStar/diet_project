02Firestore 모델링과 보안 규칙

  • 내 기록은 users/{uid} 하위, 함께 쓰는 데이터는 최상위로 분리
  • 컬렉션별 규칙(예: 친구 요청은 보낸 사람만 생성 · 받은 사람만 수락), 날짜를 정렬 가능한 키로 저장
  • 한도 대응: 삭제 300개씩, whereIn 30개씩

03서버리스 AI 파이프라인

  • 사진을 서버 함수로 보내 Claude가 음식 · 칼로리 · 영양소를 정해진 JSON으로 반환
  • API 키는 서버 Secret에만 보관, 한국어 이름 지시를 프롬프트와 스키마 양쪽에 반영
  • 외부 전송 전 사용자 동의 팝업

04계정 수명주기와 데이터 삭제

  • Apple 로그인 nonce(SHA-256), 삭제 순서: 재인증 → 토큰 철회 → 데이터 삭제 → 계정 삭제
  • 빠뜨린 소셜 데이터를 찾아 저장소 · 보안 규칙 · 처방침 문구를 함께 수정

05Repository 추상화와 구조 분리

Firestore 데이터 구조

users/{uid}                      프로필 (닉네임 · 신체 정보 · 알림 · 공개 범위)
 ├─ weight · exercise · meals    기록 — 문서 1건 = 기록 1건
 │  bowls · routines · water
 ├─ plant/state                  내 식물 (경험치 · 축 점수 · 누적 기록)
 └─ dexEntries/{speciesId}       식물 도감
publicProfiles/{uid}             친구 찾기용 닉네임 · 초대 코드
inviteCodes/{code}               초대 코드 → uid
friendRequests · friendships     친구 요청 · 확정된 관계
challenges · challengeProgress   챌린지 · 참가자별 진행
activityFeed                     친구 활동 한 줄
  • 내 기록은 users/{uid} 아래 → 규칙 한 줄로 하위 전체를 보호
  • 사용자 사이의 관계(친구 · 챌린지)는 한 사람 아래에 둘 수 없어서 최상위로 분리
  • 날짜는 'yyyy-MM-dd' 문자열(dateKey) → 사전순이 곧 시간순이라 월 범위 조회가 색인 없이 한 필드 조건으로 됨
  • 모델 ↔ 저장 형식 변환은 codec이 맡고, 예전 형식 · 깨진 값도 읽도록 처리

보안 규칙 — 기본은 전부 막고, 필요한 것만 열기

컬렉션읽기쓰기
users/{uid}/**본인본인
publicProfiles · inviteCodes로그인한 사용자 (코드로 찾아야 해서)본인 것만
friendRequests보낸 사람 · 받은 사람생성은 보낸 사람, 수락 · 거절은 받은 사람
friendships관계에 포함된 두 사람포함된 사람
challenges로그인한 사용자만든 사람(creatorId)이 생성 · 삭제, 참여는 로그인한 사용자
challengeProgress · activityFeed로그인한 사용자본인(uid) 것만, 삭제도 본인 것만

규칙은 request.auth.uid(요청한 사람) · resource.data(저장된 값) · request.resource.data(쓰려는 값)로 조건을 써요. 앱이 DB에 직접 접근하는 구조라 규칙이 곧 서버의 권한 검사예요.

A사진 분석 — 앱 → 함수 → Claude

  1. 동의 팝업 후, 사진(base64)과 그릇 정보를 Cloud Function(analyzeMealPhoto)으로 보내요
  2. 함수가 서버 Secret의 API 키로 Claude를 호출하고, zod 스키마로 정해진 JSON(음식 이름 · 영양소 · 확신도)을 강제해요
  3. 확신이 낮으면 needs_review로 표시하고, 서버에는 결과만 저장하고, 사진은 이 기기에만 보관해요
  4. 함수는 로그인한 사용자만 부를 수 있고, 한 사람당 하루 30회까지만 받아요(횟수는 서버가 트랜잭션으로 세요)

왜 서버를 거치나: 키가 앱에 들어가면 앱 파일을 풀어서 누구나 꺼낼 수 있어요

B친구 요청 — 규칙으로 권한 나누기

  1. 초대 코드를 입력하면 inviteCodes에서 상대 uid를 찾아요
  2. friendRequests 생성 — 규칙상 보낸 사람만 만들 수 있어요
  3. 받은 사람이 수락(받은 사람만 update)하면 friendships가 생겨요
  4. 활동 피드에는 짧은 한 줄만 남기고, 보이는 범위는 항목별로 사용자가 정해요

초대 코드는 헷갈리는 글자(0/O, 1/I)를 뺀 6자리예요

C계정 삭제 — 순서가 중요한 흐름

  1. 재인증(민감 작업은 최근 로그인 필요) → Apple이면 토큰 철회
  2. 내 데이터 삭제 — 기록 · 프로필 · 친구 · 챌린지 · 활동 피드(300개씩 배치)
  3. 마지막에 계정 삭제

계정을 먼저 지우면 보안 규칙이 삭제를 허용하지 않아서, 데이터를 먼저 지워요
