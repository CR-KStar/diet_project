PROJECT · 밋그린 (MEATGREEN)

사진 한 장으로 시작하는
식단 기록 앱,
밋그린

식사 사진을 찍으면 AI가 칼로리와 영양소를 추정하고, 기록할수록 식물이 자라는 다이어트 기록 앱이에요. 기획부터 구현, 테스트, App Store · Google Play 제출과 심사 대응까지 한 사이클을 경험했어요.

App Store 심사 중 (재제출) Google Play 비공개 테스트 중 Flutter · Firebase · Claude API
새 창에서 열기 ↗

웹 체험판 · 예시 데이터로 둘러볼 수 있어요. 로그인과 AI 사진 분석은 앱에서 가능해요.

120자동 테스트 (전부 통과)
2건App Store 심사 반려 → 수정 후 재제출
12명Google Play 비공개 테스트 참여
2개iOS · Android, 하나의 코드로 제출

기술 스택

Flutter / DartProvider · ChangeNotifier Firebase Auth · FirestoreCloud Functions (TypeScript) Claude APISign in with Apple / Google GitHub Pages · Firebase Hosting

만든 방식 (AI 협업)

Claude Code와 협업해 개발했고, 제품 기획과 검증, 스토어 배포, 심사 대응은 직접 진행했어요. 구현한 코드를 이해하려고 구조를 따로 다시 만들어 보며 공부하고 있어요. 앱 아이콘의 캐릭터 이미지는 AI로 생성했어요.

이 프로젝트에서 보여드릴 수 있는 것 5가지

각 항목은 실제로 겪은 문제와 해결 과정이에요. 코드는 GitHub에서 확인할 수 있어요.

01

스토어 출시와 심사 대응 전 과정

무엇을
iOS 서명·TestFlight·App Privacy, Google Play 데이터 보안·콘텐츠 등급·개인 계정 비공개 테스트(12명, 14일)를 진행했어요.
어떻게 풀었나
App Store 반려 2건(건강 정보 출처 1.4.1, Apple 로그인 2.1)을 원인 분석 후 수정해 재제출했어요.
배운 점
앱은 "만드는 것"과 "내보내는 것"이 다르고, 심사 기준을 코드와 문서에 반영해야 해요.
02

개인정보·데이터 보호 설계

무엇을
계정 삭제 시 친구·챌린지·활동 피드까지 서버 데이터를 지우고, Apple 토큰도 철회해요. 외부 AI로 사진을 보내기 전 동의 팝업을 받아요.
어떻게 풀었나
삭제가 빠뜨린 데이터를 찾아 저장소 코드, Firestore 보안 규칙, 처방침 문구를 함께 고치고 테스트로 보호했어요.
배운 점
규정 준수는 문서가 아니라 동작으로 증명해야 해요.
03

구조 설계와 테스트 진행 중

무엇을
Repository 패턴, ViewModel 분리(물·체중 완료, 식단 진행 중), 시계를 주입해 날짜를 고정하는 테스트를 만들었어요.
어떻게 풀었나
3,400줄짜리 상태 클래스를 영역별로 나누고, 한 단계마다 테스트가 통과하는지 확인해요.
배운 점
데이터의 원본을 한 곳에 두면 화면 간 어긋남이 줄어요.
04

AI 기능 통합 (사진 → 영양 분석)

무엇을
사진을 서버 함수로 보내 Claude가 음식·칼로리·영양소를 정해진 JSON 형식으로 돌려주게 했어요.
어떻게 풀었나
API 키는 앱이 아니라 서버에만 두고, 이름이 영어로 나오는 문제는 프롬프트와 스키마 양쪽에 한국어 지시를 넣어 해결했어요.
배운 점
AI 출력은 검증 가능한 형식과 사용자 동의 흐름이 같이 있어야 해요.
05

사용자 경험의 세부 완성도

무엇을
오늘 기록 여부에 따라 바뀌는 동적 앱 아이콘(iOS·Android 방식이 서로 달라요), 글자 크기 배율 대응, 디자인 토큰, 로그인 없는 웹 체험판을 만들었어요.
어떻게 풀었나
iOS는 대체 아이콘 API, Android는 activity-alias로 구현하고, 화면 오버플로를 점검해 어떤 기기에서도 깨지지 않게 했어요.
배운 점
플랫폼마다 다른 기능은 같은 인터페이스 뒤에 숨기면 앱 코드가 단순해져요.
